# Business Entity Resolution Challenge

A machine-learning system that, for every entity in **Source 1**, finds zero, one,
or multiple matching entities across **Source 2** and **Source 3**.

## Member 1 – Data Loading, Preprocessing & Candidate Blocking

### What it does

| Module | Responsibility |
|--------|---------------|
| `backend/data/loader.py` | Load any TSV source with validation; auto-detects all countries |
| `backend/preprocessing/normalizer.py` | Normalize business names (legal suffixes, Unicode, punctuation) and addresses (abbreviations, postal tokens) |
| `backend/blocking/blocking.py` | 6-strategy blocking engine – exact name, token overlap, country+token, address token, postal code, TF-IDF cosine |
| `backend/blocking/candidate_generator.py` | Orchestrates load → normalize → block → write `output/candidate_pairs.tsv` |

### How to run the candidate generation pipeline

**Using test data** (default):

```powershell
# From the project root
python -m backend.blocking.candidate_generator
```

**Using training data:**

```powershell
python -m backend.blocking.candidate_generator --train
```

> **Note**: If official TSV data files are not present under `dataset/test/` or `dataset/train/`,
> the pipeline automatically generates a **tiny synthetic dev dataset** for smoke-testing.
> Place the official `.tsv` files in the appropriate `dataset/` subdirectory to run on real data.

### Output

`output/candidate_pairs.tsv` – tab-separated, two columns:

| Column | Description |
|--------|-------------|
| `source1_entity_id` | Every S1 entity; one row each |
| `candidate_entity_ids` | Comma-separated S2/S3 candidate IDs (may be empty) |

**Guarantees:**
- Every Source 1 entity has exactly one row
- Candidate IDs are only from Source 2 or Source 3 (never S1 self-matches)
- Duplicate candidate IDs are removed
- Countries are open-set (US, France, India, Germany, … all supported)

### How to run the tests

```powershell
python -m pytest tests/test_member1.py -v
```

Expected: **37 tests pass** covering:
- TSV loading (valid files, missing files, missing columns, multi-country)
- Business name normalization (lowercase, Unicode, legal suffixes, punctuation, `&`→`and`)
- Address normalization (abbreviations, digit preservation, Unicode)
- Tokenization and postal code extraction
- Blocking correctness (every S1 row present, no self-matches, no invalid IDs, known matches found)
- Country open-set handling (France, Germany, India, Ruritania, …)

## Blocking strategies (Member 1)

1. **Exact normalized name** – fastest, highest precision
2. **Name token overlap** – inverted index on name tokens (≥ 1 shared token)
3. **Country + name token** – same as #2 but scoped to matching country
4. **Address token overlap** – inverted index on address tokens (len > 2)
5. **Postal-code token** – extracts ZIP / postcode patterns and matches
6. **TF-IDF cosine** – character n-gram (2–4) TF-IDF with cosine ≥ 0.25; catches OCR/abbreviation variants

## Data format

All files are **tab-separated** (TSV) with these columns:

| Column | Description |
|--------|-------------|
| `entity_id` | Unique identifier |
| `business_name` | Business name (raw) |
| `business_address` | Business address (raw) |
| `country` | Country string (open-set – do **not** hard-code) |

## Important rules

- All data loaded with `pd.read_csv(file, sep="\t")`
- Never use external APIs (Google Maps, geocoding, business databases)
- Never hard-code countries; the system supports any country in the data
- Never push with `--force`; one shared `main` branch
